# Talking back to the kit

**When:** after adopting, after an upgrade, and any time the conventions fought you.

## Why this exists

The kit only learns from homes that report. Every tier it has beyond the first draft came from
someone saying "this did not fit": the obligations gap, the reversal line on re-decided rulings,
the generated-index rule. A home that adopts and reports nothing has taken from the kit without
paying it.

## What is worth reporting

- **What fit no tier.** Quote it. This is the most valuable thing you can send, and the easiest
  to leave out because it looks like your own mess rather than the kit's gap.
- **Caps that were wrong for your home**, with the number. "Thirty facts per file is too few
  for us, we run ninety" is a finding. "It felt tight" is not.
- **Where conversion needed judgment** and how much of it did -- that is the cost of adoption,
  and the kit has no other way to learn it.
- **What the first week broke.**

## What is not worth reporting

Your home's content. Roles and shapes, never identities; run the redaction checklist first.
The kit needs to know that a tier was missing, not who was in the missing record.

## How

An issue on the kit's tracker, titled as an experience report. State your scale (files, claims,
how long the home has run) so the finding can be weighed. If a fix is obvious to you, say it --
but the report is worth filing without one.

## The bar for a rule reaching `memory/`

If your finding becomes a proposed core rule, it must name the specific, repeated, recorded
mistake a home would make without it. Core costs every adopting home a spawn row forever. No
incident, no core -- it is a lesson, and lessons are free.
